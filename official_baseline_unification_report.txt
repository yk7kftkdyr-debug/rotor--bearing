Official baseline unification report
====================================

Purpose
-------
This update removes the main parameter-mixing risks before large batch
simulation. It does not change the bearing contact law, rotor/casing
matrices, Newmark iteration logic, thermal correction formula or existing
post-processing workflow.

Official baseline
-----------------
Bearing layout:
  bearing1 = front high-speed angular contact ball bearing
  bearing2 = rear high-speed cylindrical roller bearing

Bearing nodes:
  bearing1 rotor/casing node = 2 / 3
  bearing2 rotor/casing node = 10 / 10

Baseline preload:
  bearing1 ball preload_z = 20 kN
  bearing2 roller preload_z = 80 kN

Load application:
  The above loads are used only as bearing quasi-dynamic preloads.
  They establish bearing contact state, loaded rolling-element number,
  working clearance and equivalent support parameters.
  They are not applied as rotor-node static_load in the coupled dynamic
  equation. Official baseline static_load.Fx and static_load.Fy are zero.

Unified source files
--------------------
official_simulation_config.m
  Single source for official baseline preload, static_load, Newmark model
  directory, default Fen and timestep-convergence Fen list.

apply_official_case_config.m
  Applies the official baseline to params. Usually this file should not be
  edited unless the load-application rule itself changes.

bearing_layout_config.m and enforce_bearing_layout.m
  Define and enforce front ball bearing / rear roller bearing layout,
  including bearing types and rotor/casing nodes.

initial_conditions.m
  Main parameter entrance. It still defines speed, unbalance, lubricant,
  clearances, solver settings and contact switches, then applies the
  official baseline at the end.

thermal setup
-------------
热效应相关程序/setup_thermal_case_common.m now applies the same official
baseline while preserving its own thermal output paths and temperature
settings. Thermal studies should change temperature, oil properties,
thermal clearance and related thermal options there or in the thermal
runner options, not by rewriting baseline preload values.

Newmark model guard
-------------------
Official runs require the uploaded/local Newmark rotor-casing model
directory:
  Newmark解故障轴承

If the required Newmark files are missing, the official run now stops with
an error instead of silently falling back to the simplified beam model.
The fallback model remains available only for non-official exploratory
tests where require_uploaded_rotor_model is false.

Consistency guard
-----------------
validate_official_case_config.m checks:
  bearing1 is ball and bearing2 is roller;
  bearing rotor/casing nodes match the official layout;
  preload is 20 kN / 80 kN;
  rotor-node static_load is zero;
  local Newmark model directory exists.

main.m, setup_thermal_case_common.m and newmark_newton_multi.m call this
guard for official baseline runs.

Disabled/deleted legacy wrappers
--------------------------------
The following old alternative entry points were moved out of the active
execution folders to avoid accidental mixed results:
  main_strong_coupled_rotor_bearing.m
  run_strong_coupled_rotor_response.m
  run_macos_desktop_simulation.m
    Old alternative entry points that could bypass the official baseline
    configuration and reporting guard.

They are preserved in disabled-entry folders:
  历史入口_禁用/
  热效应相关程序/历史入口_禁用/

The old 20/100 kN and 100/150 kN thermal/preload candidate scripts were
deleted by request:
  run_high_load_T50_case.m
  run_high_preload_T50_case.m
  run_preload_20_100_Fen4096_check.m
  finalize_preload_20_100_Fen4096_report.m
  run_preload_20_100_Fen4096_check_original_backup.m

Historical backups
------------------
Original backup files were moved out of the executable root folders:
  历史备份_禁用/
  热效应相关程序/历史备份_禁用/

This keeps rollback files available while reducing the chance that MATLAB
accidentally calls an old backup version from the active working directory.

Time-step risk handling
-----------------------
The default official Fen remains 1024 to avoid changing the original
runtime burden. The official configuration records the required
time-step-convergence list:
  Fen = [1024 4096 8192]

Reports now state that high-frequency acceleration/contact-modulation
interpretation must be supported by this time-step convergence check.

Quick check
-----------
Run this without starting a full simulation:
  run_official_parameter_check

It verifies the official baseline preload, static_load, bearing layout,
Newmark directory and thermal common setup.
